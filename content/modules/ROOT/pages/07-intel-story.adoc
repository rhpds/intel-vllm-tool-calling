= Module 7: Evaluate CPU Inference for Tool Calling

_Estimated time: 5 minutes_

Tool calling alternates model inference with application or tool execution. Measure both parts before selecting serving hardware. Short responses and time spent waiting for tools can make CPU inference a useful option; model size, concurrency and latency targets still determine whether it meets your requirements.

== What This Guided Lab Demonstrates

The guided path uses a shared MaaS endpoint. Your namespace contains the client workload, not the shared model server. A successful tool call proves the API contract and application behavior. It does not establish the backend processor, accelerator, resource consumption or cost.

Ask the platform owner for the model revision, serving runtime, processor and accelerator placement, quantization, allocated resources and request limits before making an Intel CPU performance claim. Node names and CPU counts alone do not prove these details. Cluster-wide node access is not required for this lab.

== Record Application Evidence

Use the tool loop from Module 4 and record:

* Model name and serving profile supplied by the platform owner
* Time for model responses and time spent executing tools, separately
* Whether the model selected the expected tools and used their returned results
* Failures, retries and behavior under concurrent requests

Repeat the same workload with the same model revision, prompt, token limits and concurrency when comparing CPU and GPU serving. Include warm-up, time to first token, end-to-end latency, throughput and tool-call correctness.

== Evaluate the Intel Deployment Option

Intel Xeon deployments can use runtime-specific CPU optimizations. Confirm the actual processor features and runtime configuration with the serving team. The standalone quickstart offers a separate path for deploying and measuring a CPU model; the guided MaaS path does not deploy that model into your namespace.

Compare measured capacity and quality against your service targets. Account for hardware allocation, utilization, power, operations and serving charges. Existing CPU capacity still has a cost; this lab supplies no measured price or savings estimate.
